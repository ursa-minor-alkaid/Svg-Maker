# 文字输入需求工作流

### 第一步：需求判断与分类

| 类别 | 特征 | 处理方式 |
|------|------|----------|
| **文字-模糊需求** | 仅给出主体名称或者核心思想，如"画一只黑猫""生成一个火箭 SVG""生成一个用于展示、具象化项目核心原则的、富有设计感、艺术感的简洁的 icon svg"| 先搜索网络获取参考，自行撰写详细提示词，再生成 |
| **文字-明确需求** | 给出了非常非常详细的提示词和细节描绘 | 直接进入结构化提示词生成阶段 |

**注意：任何字数小于60字/90tokens的需求，都视为模糊需求**

---

### 第二步：模糊需求处理

1. **WebSearch**：
   - 搜索该主体的视觉特征描述、结构拆解、已有代码参考
   - **使用多种提示词组合进行多次的、全方位的搜索**
   - 详细的搜索及发返回提示词详见：[搜索提示词](references/SearchPrompts.md)（路径：`references/SearchPrompts.md`）
2. **向用户展示、并寻求反馈及确认**
   - 将当前的搜索结果汇总后，简要地告诉用户绘制思路，并询问是否符合预期、是否有信息需要补充
   - 若用户补充了较多信息，则重新搜索并更新搜索结果
   - **将前述搜索结果和用户补充信息汇总整合，进入结构化提示词生成步骤**

---

### 第三步：结构化提示词生成

生成代码前，按四个层次组织提示词：

#### 1. 场景级（Scene-level）
- 列出必须出现的核心对象，补充颜色、大小、姿态等视觉细节
- 克制添加辅助元素，仅当明显增强场景完整性时才加

#### 2. 对象级（Object-level）
- **穷尽每个对象的关键部件**，含常识性部件（如画猫须含耳、眼、须、尾、四肢），遗漏即不存在
- 每个部件标注 SVG 元素类型（`rect` / `circle` / `ellipse` / `line` / `polygon` / `polyline` / `text` / `g`）
- 用最少部件实现效果，避免冗余

#### 3. 布局级（Layout-level）
- 为每个部件规划精确坐标与尺寸，可直接翻译为代码
- 规划绘制顺序：按"背景 → 主体 → 细节"排序，后定义者在上层
- 标注部件间连接/遮挡关系，确保衔接不悬空
- 被包围的部件用可区分颜色，防止不可见

#### 4. 技术规范
- **viewBox** 尺寸（如 `0 0 800 600`）
- **元素集**：基础形状优先，必要时允许短 `<path>`（≤5 条命令、以 `Z` 结尾）
- **颜色**：十六进制色值，明确背景色、主体色、强调色
- **代码**：元素加 `id` 和注释，`<g>` 分组；圆角用 `rx`；禁渐变、滤镜、裁剪路径（除非用户要求）

---

### 第四步：SVG 代码生成规则

将第三步规划**逐条翻译**为代码，不即兴发挥、不遗漏：

1. 按规划顺序书写，背景最先；相关元素 `<g>` 分组加语义注释
2. 十六进制色值；无背景时避免纯白形状
3. `<text>` 明确 `x`, `y`, `font-size`, `fill`
4. **生成后自检**：部件完整 / 连接对齐 / 比例合理 / 叠放正确
5. 确保主流浏览器可直接渲染，不依赖外部资源
