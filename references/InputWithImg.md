# 含图片输入需求工作流

针对"根据图片复刻生成 SVG"的需求。视觉模型读图的固有弱点：单遍扫读丢失细节、绝对坐标估计不准、非文字元素的空间定位弱。本工作流以**多遍分区读取 + 文字化转写 + 相对坐标推算 + 渲染对照修正**补偿这些弱点。

---

### 第一步：图片结构化读取（多遍扫描）

按以下顺序多遍读取，把视觉信息**全部转写为文字清单**——文字通道的可靠性远高于凭视觉记忆直接生成：

1. **整体扫读**：判断图类型（图标 / 插画 / 图表 / 流程图 / UI 界面 / 论文方法图）、构图布局、配色基调、背景与主体
2. **文字与公式优先**：完整读出图中所有文字（标题、标签、图例、注释）与公式，逐字记录内容与所在位置；公式须读出上下标结构（如 U 下标 mid）。内容必须来自本轮读取，禁止凭"常见样式"补写
3. **分区读取**：将画面按九宫格（或上中下、左中右）划分，逐区记录元素：形状、颜色、相对位置、层叠关系
4. **细节补读**：对关键局部（小图标内部、线条走向与端点、箭头方向、装饰元素）单独细读，补充进清单

**输出**：元素清单，每项含 `文字内容或部件名 — 形态 — 相对位置 — 颜色`。清单穷尽所有可见元素，遗漏即不会出现在成品中。

---

### 第二步：结构化提示词生成

将元素清单组织为四层提示词：

#### 1. 场景级
按图层划分：背景层 → 主体层 → 细节/装饰层 → 文字层，明确各层范围与遮挡关系。

#### 2. 对象级
- 每个可视元素映射为基础形状（`rect` / `circle` / `ellipse` / `line` / `polygon` / `polyline` / `text` / `g`）
- 图中文字一律用 `<text>` 重写，不描字形；公式用 `<text>` + `<tspan>` 表达：下标 `baseline-shift="sub"`，上标 `baseline-shift="super"`，特殊符号用实体（`&#8730;` √、`&#931;` Σ、`&#916;` Δ）；**禁止出现 LaTeX 原文**（如 `\sqrt{}`、`\Delta`），禁止把公式截图化
- 流程图类：箭头用 `line`/`polygon` 组合；连线走**正交线**（水平 + 垂直），避免斜线交叉；连线接到模块边缘，不插入模块文字

#### 3. 布局级——相对坐标推算
**禁止凭像素直觉直接报绝对坐标**。推算流程：
- 以画面宽高为 100%，先估各元素的相对位置与相对尺寸（如"标题栏占顶部 12%，按钮位于右下角，宽约为画面 1/5"）
- 换算公式：`绝对坐标 = 相对比例 × viewBox 对应维度`
- 同排/同列元素先定基准线（同一 y 或 x），再排布，保证对齐
- 有网格感的图（图表、UI）先画网格参考线定骨架，再填元素

#### 4. 技术规范
同[文字输入需求工作流](InputWoImg.md)第三步第 4 层：viewBox、元素集、十六进制色值、`id` 与注释、`<g>` 分组、`rx` 圆角、禁渐变/滤镜/裁剪路径。另：
- 含中文时必须加 UTF-8 声明：`<?xml version="1.0" encoding="UTF-8"?>`（防乱码）

**注意**：**不要私自添加无关的、原图中不存在的细节或文字**；不得私自扩充；**必须一精准地还原原图为第一要义**。

---

### 第三步：代码生成

将第二步规划**逐条翻译**为代码，规则同[文字输入需求工作流](InputWoImg.md)第四步：按"背景 → 主体 → 细节 → 文字"顺序书写、十六进制色值、`<text>` 明确 `x`/`y`/`font-size`/`fill`、不即兴发挥。公式尽量在一个 `<text>` 内完成，过长时优先缩小字号而非断行。

---

### 第四步：渲染对照修正（闭环）

生成后在脑中"渲染"，与原图**分区对照**，逐项核对视觉模型的典型出错点：

- **细节遗漏**：第一步清单中的小元素、装饰是否全部画出（最常见缺陷）
- **位置偏移**：元素间左右、上下关系是否与原图一致
- **比例失真**：部件大小关系是否失衡（如按钮过大、间距过宽）
- **对齐错误**：同排文字基线、线段端点、模块边缘是否对齐；连线是否穿过文字/公式/标题
- **文字与公式**：是否有错字漏字、乱码；公式是否残留 LaTeX 原文、上下标是否正确、是否溢出模块
- **颜色偏差**：允许近似取色，但色相深浅不能颠倒
- **层叠错误**：前景是否被背景遮盖

发现问题**针对性修正**，不整体重绘。修正后重新对照，直至无结构性差异。
